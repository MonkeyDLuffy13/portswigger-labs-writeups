# Lab 05 — 0.CL request smuggling

> **Expert** · [Official lab](https://portswigger.net/web-security/request-smuggling/advanced/lab-request-smuggling-0cl-request-smuggling)

**Entry point:** 0.CL desync — the front-end forwards the request without a
usable body length (treats it as zero), while the back-end honors
`Content-Length`, swallowing the next request as "body".

## Solution

1. Send a POST with a `Content-Length` but an **empty body**; the back-end
   waits for the bytes and consumes the following request on the
   connection:

```http
POST / HTTP/1.1
Host: YOUR-LAB-ID.web-security-academy.net
Content-Length: <length of smuggled request>

<smuggled request bytes>
```

2. As with the other desyncs, smuggle a poisoned redirect / admin request
   (the official lab page links a livestream walkthrough — follow the
   connection-poisoning flow used in the H2.CL lab) — lab solved.

## Notes

"0.CL" = front-end assumes 0-length body, back-end trusts CL: any
request-gap on the connection becomes a smuggle primitive.
